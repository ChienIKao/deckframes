# 用知識圖譜輔助設備故障診斷

## 介紹 | Introduction

### 研究動機

#### 為什麼故障診斷很重要 | 逐點出現

- 停機一小時的損失遠高於維修本身
+++
- 資深技師的經驗難以傳承
+++
- 手冊與工單分散在不同系統

<!-- 第三點講完再切到下一頁 -->

#### 三個核心價值 | 卡片逐張出現

```steps build
- 提升設備可靠度 | 減少非預期停機 | icon: shield-halved
- 加速問題排除 | 從症狀直接找到原因 | icon: magnifying-glass
- 降低訓練成本 | 新人也能照步驟處理 | icon: user-graduate
```

#### 針對三大困境的解決方案

```mapping build=focus left=Problem right=Solution
- 知識散落各處 -> 建立故障知識圖譜 | icon: diagram-project
- 無法結合即時數據 -> 感測特徵寫入圖譜 | icon: wave-square
- 規則無法更新 -> 回饋迴圈持續學習 | icon: rotate
```

+++ overlay

- **什麼是知識圖譜？** 把設備、警報、原因與解法存成節點與關係，查詢時沿著關係找答案。
- **為什麼需要回饋？** 現場的新案例每天都在增加，圖譜要能吸收工程師確認過的新解法。

## 研究方法 | Method

### 系統架構

#### 系統架構圖 | 元件依序出現

```diagram build
- 維修工單 -> 圖譜建構
- 設備手冊 -> 圖譜建構
- 圖譜建構 -> 知識圖譜
- 知識圖譜 -> 檢索模組
- 使用者提問 -> 檢索模組
- 檢索模組 -> 診斷建議
group 離線建構: 維修工單, 設備手冊, 圖譜建構
group 線上服務: 檢索模組, 診斷建議
```

+++ focus=圖譜建構,知識圖譜

> [!TIP] 先把工單與手冊整理成固定的實體類別，再寫入圖譜。

#### 檢索流程 | 前一步淡出，新步驟接上

```flow
- 收到提問
- 比對警報碼
```

+++ dim

```flow
- 沿關係找原因
- 排序解法
```

### 實驗結果

#### 各模型表現 | 數值皆為示意

| 模型 | 參數量 | 準確率 | 回應時間 |
|---|---|---|---|
